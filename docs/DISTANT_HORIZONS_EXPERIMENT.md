# Experimental Distant Horizons path

This is an experimental path, disabled by default. It has been visually validated in-game in one configuration (see the playtest observation below). It targets the official Distant Horizons 3.3.4 Fabric release for Minecraft 26.3. The preflight checks the mod version and selected compatibility-critical classes against the official release, independently of JAR filename or ZIP packaging. Copies with the same checked classes can pass; modified builds that change those classes are rejected. This is not a guarantee for every modified build, since other classes and resources are not fingerprinted. Other versions, Iris, an OpenGL DH engine, or an unreadable configuration keep Pure Metal's existing backend fallback.

To opt in, start the client with `-Dpuremetal.experimentalDistantHorizons=true`, without Iris, and use DH's `AUTO` or `BLAZE_3D` renderer. When the property is set and DH is installed, the F3 "Pure Metal" line ends with `DH: experimental on`, or `DH: off (<reason>)` when the preflight fell back (Iris, version, modified build, engine setting, config unreadable, preflight error). The log has one plain WARN per cause, for example the DH version found against the 3.3.4 required, or the engine DH is set to and the fix (set DH's rendering engine to AUTO and restart). There is no in-game chat message. Without the property, or without DH, nothing is logged or shown. Remove that JVM property and restart to turn the experiment off. This does not change the DH config. The existing `puremetal.ignoreIncompatibleMods` override bypasses the normal safety guard and can force an incompatible DH setup onto Metal; do not use it to enable this experiment.

DH 3.3.4 incorrectly reports Metal as OpenGL. The experiment follows the approach used by mcopt: only when Pure Metal is active, it gives DH the `VULKAN` API value so that DH's Blaze3D renderer avoids OpenGL-specific code. DH continues to send draw requests through the Metal backend. The label is a compatibility workaround, not a claim that the device is Vulkan. Other mods may interact with DH's reported API or change its configuration at runtime; those combinations have not been verified.

Builds and headless checks cannot establish that DH renders correctly; only in-game testing can. The single in-game observation below covers one configuration. Other dimensions, other upscaler and render-scale settings, errors over longer sessions and controlled GPU performance measurements still require separate validation before shipping this as supported.

Run `python3 tools/test_distant_horizons.py /path/to/DistantHorizons-3.3.4.jar` with Java 25 for the headless engine-selection, release-class fingerprint and Fabric transformation checks.

Playtest observation (2026-10-28): with Pure Metal's Metal backend active, DH rendered correctly in-game on an Apple M2 (Metal 3) with Sodium 0.9.3-beta.1, render scale 50% with MetalFX Temporal and a DH LOD distance of 256 chunks. The in-game FPS counter read about 155, a single reading and not a benchmark. Only this configuration was observed; the dimension and measurement duration were not recorded.

To remove the code experiment, remove `DistantHorizonsExperiment.java`, `mixin/compat/DistantHorizonsApiMixin.java`, `tools/TestDistantHorizonsExperiment.java`, `tools/TestDistantHorizonsKnot.java`, `tools/test_distant_horizons.py` and this document, plus the one-line gate in `PureMetalBackend.java`, the gate in `PureMetalMixinPlugin.java`, and the mixin entry in `puremetal.mixins.json`. Preserve the surrounding uncommitted changes in those files.
